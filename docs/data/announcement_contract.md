## 生产入口与证券身份

公告生产并入 `run_offline_data(kind="data-standard")`，与基础来源共用显式自然日期范围。
披露日事实与登记日公司行动处置分别发布，后者才要求相应 dividend 覆盖对象。
公告范围包括周末，不按回测交易日过滤，也不设置统一回看天数。当前证券组织映射仅用于
定位来源，不定义历史股票池；历史代码不能对应时保留明确问题，不能推测映射或静默跳过。
沪深历史代码通过可选 `identity_refs` 传入已复核的对应关系 JSON；每项包含现代码、
公告原代码、官方原文 URL 与 `evidence_file` 文件名，JSON 同目录须有该原件。
采集保存对应关系和原件，允许索引返回已证明的旧代码；组织 ID 本身
不作为股份连续性的证明。`000043 → 001914`、`000022 → 001872` 均有发行人代码变更、
原投资者持股数量不变的公告依据。`300114 → 302132` 则由
[2025-02-15 代码变更公告](https://static.cninfo.com.cn/finalpage/2025-02-15/1222544408.PDF)
确认；2018-05-15 登记的原实施公告仍使用 `300114`，实际税前每股派 0.05 元。
较晚的代码对应证据只用于识别同一证券，不将变更日期、未来交易状态或分红条款提前
用于账户决策。没有被证据覆盖的其他代码仍拒绝，PDF 原代码不改写。

```python
run_offline_data(
    app_config=app_config, path_manager=pm,
    submission=DataSubmission(kind="data-standard", start="2026-08-20", end="2026-10-17"),
    review_refs=(Path("/inputs/reviewed-distributions.json"),),
)
```

链路的共同顺序及历史补齐边界由[工作流 owner](../offline_workflow_contract.md#standard-历史补齐与日常生产)定义。
`CollectAnnouncementsStep/CollectBseAnnouncementsStep` 仍是已知登记日调查的内部组件，
不再组成另一套独立业务入口；按原登记日关联、提取、确认及发布的规则继续适用。

## 自然披露日索引与事实物化

日常与历史公告统一通过 Standard 链中的 `CollectPublicationsStep` 按自然披露日采集，
两来源的公开索引均不以本地证券或 dividend 候选过滤；巨潮不限“权益分派”类别。重整早期
披露、实施、补充、更正、取消和终止等候选原文进入 `MaterializeAnnouncementFactsStep`。
一般财务报告全文理解不属于本次公司行动提取器覆盖，索引覆盖与正文事实覆盖分别表达。
网络、分页、原件下载失败保持失败及重试；不可读 PDF 保留 `parse_issue`，不伪装成无事件。
已有候选反查全部截至请求结束日的本地披露索引，确保公告先到、dividend 后到仍能关联；
不得为了填满历史字段查询请求结束日之后的新公告。

[CollectPublicationsStep](../../src/data_system/steps/collect_publications.py) 对请求闭区间内每个
自然日查询两个渠道；即使已有索引仍重新查询，才能发现新增或更正。还会重试不晚于请求
结束日、任一渠道缺 Meta 或保留 `pending.json` 的已发现日期分区。成功处理的日期写入
`DataContext.publication_dates`，供后续事实物化识别本次补采的历史日期；不修改请求范围或交易日列表。

[PublicationIndex](../../src/data_system/announcement_publications.py) 固定包含 `version=v1`、
`source`、`publication_date`、`announcements`。每条 `AnnouncementPublication` 包含
`source`（cninfo/bse）、`announcement_id`、六位 `symbol`、`title`、`published_date`、
可空的 `published_ts_us` 和原文 `url`。同一索引内原生 ID 唯一，来源和披露日必须与分区一致。
`PublicationCoverage` 单独保存 `index_count`、带时区的 `observed_at` 及请求证据文件名
`request_files`；索引内容相同保留原 payload 与 Meta，仍更新查询覆盖记录。
完整空索引表示该来源当日查询无记录，不等于文件缺失。路径、重试标记和原件文件名统一由
[存储 owner](storage_layout.md#公告披露日对象)定义。

[MaterializeAnnouncementFactsStep](../../src/data_system/steps/materialize_announcement_facts.py)
读取截至 `end` 的本地已提交索引，按自然日及公开可见时刻处理候选原文；请求范围内、
本次补采和尚无事实分区的日期重新物化。请求起点之前已有且本次未补采的事实仅用于
后文关联，不重新下载。标题粗筛由 `is_distribution_evidence` 定义：分派、分配、分红、
派息、转增、转赠、除权除息、重整、业绩补偿以及更正、补充、修订、取消、终止进入候选；
标题命中回购/转股/发行/授予/行权价格，或“律师”“独立财务”“激励计划”“募集资金”
“分红回报规划”时，不进入该自动事实物化集合。标题只决定提取范围，不证明发生分配或事件已可执行。

PDF 原件、下载回执与可读取页文本分别保留；无法读取的原文形成 `parse_issue`，不缓存
伪造的成功空文本。重跑保留相同原生公告首次事实观察时间 `observed_at`，比较完整表内容
及输入路径，未变化时复用事实文件；成功解析的空候选集合也发布空表。完整字段和物理类型
见[存储 owner](storage_layout.md#公告披露日对象)，读取缺失/空集合与校验规则见
[Access owner](../engineering/access.md#公司行动对象读取)。

## 事件进入、事实补齐与账户投影

`announcement_facts/v1` 是披露日事实表，不是全量核验通过表。其逻辑模型为
[AnnouncementFacts](../../src/data_system/announcement_facts.py)，每行对应一份原生公告：

| 字段 | 含义与取值 |
| --- | --- |
| `event_id`、`publication` | 稳定事件身份及完整原生公告身份；公开可见时间由 publication 给出 |
| `observed_at` | 系统首次物化这份公告事实的时间，独立于历史公开时间 |
| `kind` | `distribution`、`reorganization`、`compensation` 或 `other` |
| `benefit_state` | 可空；`announced`、`conditional`、`confirmed`、`cancelled` |
| `record_date`、`ex_date`、`pay_date` | 已披露的登记、除权除息和现金支付日期 |
| `shares_credit_date`、`shares_available_date` | 普通账户股份到账与上市/可交易日期，分别保存 |
| `cash_per_share`、`shares_per_share` | 普通股东每股税前现金与净获配股份，Decimal，非负 |
| `shares_numerator`、`shares_denominator` | 原始分配整数股数与受益持股分母，前者非负，后者为正 |
| `reference_cash_per_share`、`reference_shares_per_share`、`reference_price` | 市场参考参数或直接参考价，与账户实得权益分开 |
| `is_revision`、`conflicts`、`parse_issue`、`evidence_refs` | 是否为修订、字段冲突、解析问题及证据 URL |

阶段日期、金额、比例、公式整数和参考字段均允许尚未披露；未知保存 null。
已确认零、附条件安排、取消及冲突各有独立表达。
分子先到、分母后到可分别保存；只有实际数量计算才要求完整分母或正式净比例。公司整体
扩股比例不填入普通股东净比例，除权参考价也不替代个人应得金额。

事件初始身份采用首次关联公告的 `source:announcement_id`，不含未来才明确的登记日。
自动跨文档关联需要同证券、明确引用原公告标题和日期；只有同公司、同日期、最新文件或
相似比例不足以归并。不能证明关联的材料独立保留；多个引用指向不同事件时标记
`event_link` 冲突，不猜测唯一事件。已确认 review 及其 related_sources 继续优先；与既有
登记处置重叠的公告不另发一笔权益，特殊事件缺关联时保留账户关联待处理诊断。

同一事件按公开时间累计事实。后文省略某项不删除已知值；相同原生公告或相同事实不重复
登记。不同值默认是冲突，明确更正且有严格较晚的可见时间才能替换该字段；同日只有日期的
互相矛盾文本没有可靠先后，不按公告 ID 排序决定真值。取消是后续事实，不删除事件历史。
真实更正若影响已确认/结算账户阶段，须独立账户调整，不能重写历史流水。

时间分为业务阶段时间、公开可见时间、系统实际观察时间。`available_ts_us` 使用经索引
证实的 `published_ts_us`；只有日期时使用下一自然日 Asia/Shanghai 00:00 对应的 UTC
微秒，精确时刻对应的上海本地日期必须等于 `published_date`。例如 2026-09-19 只有日期的
公告从 09-20 零时可见，不能填入 09-19 盘前事实。历史公共信息回放按公开时间
过滤；复现实盘信息延迟时再要求 observed_at 不晚于当时系统时刻。今天下载的历史文件不
证明系统过去已经采集，也不证明源端历史数据库版本；这里不添加摘要或原文件变化检测。
`Access.announcement_history/announcement_events` 必须先过滤再累计。筛选、特征和账户
共享该视图，不能拿最终修正版构造早期特征，也不能只保留最后成功实施的事件作为训练样本。
当前不擅自增加模型特征列；具体特征、标签成熟日仍由对应 owner 定义。

公告 facts 保存成功、事件足够关联、权益足够计算、可用现金/股份完成入账是不同结果。
正常等待补充、解析问题、事实冲突和账户因缺事实不能推进分别保留，不能把前两者都叫
“公告核验不通过”，也不以未解决数量归零代替数据质量验收。后续公告可能没有新增必要
事实，重复内容可跳过；不能承诺下一份 PDF 必然包含全部缺项。

### 采集与完整性

`CninfoBroker` 使用公开公司索引和 `static.cninfo.com.cn` 原文路径；
每页按 30 条请求，以 totalAnnouncement 和唯一公告 ID 数量验证。跨页重叠时按自然日
二分；单日仍重叠时补查反向排序。索引查询遇到 500/502/503/504 时最多请求三次，
等待分别为 1 秒、2 秒，每次响应均保留；403 等其他状态立即失败。数量变化、同 ID
字段冲突、范围外记录、无法补齐的截断、最终 HTTP/PDF 错误均失败，不提交成功集合。
登记日定向调查中，已实施候选查到空公司索引不能证明公告不存在，
同样失败；该调查某渠道没有候选时不查询该渠道。自然披露日的全市场采集仍查询两个渠道，
允许完整空索引。保存原始请求参数、响应、数量、来源 URL、
公告 ID、证券身份、源公开日期、独立采集时间及证据文件路径。公开日期取索引时间按
Asia/Shanghai 转换；没有经过验证的盘中发布时间不进入回放。PDF 缓存保留首次采集时间，
复用按公告身份和查询覆盖范围判断，不重新校验文件内容，不依赖临时核查路径。
条款提取分别核对两个渠道覆盖其负责的全部已实施候选，不能把部分证券采集
冒充整个来源分区的完整集合。渠道尚未采集时，其候选保留 `announcements_not_collected`
及渠道名，其他已有完整证据的候选仍可核验；这些处置不表示整体覆盖已通过。
旧集合缺少某些证券时，在公告查询范围一致的条件下补采缺少证券，再发布完整集合；不把旧的沪深覆盖当成
已经覆盖北交所。
全市场目录单日双向排序仍无法补齐时，按官网公布的深市、沪市、北交所板块拆分；必要时
再拆深主板/创业板、沪主板/科创板。最小板块仍有重叠时，按本次公开索引已返回的
`secCode,orgId` 查询发行人，不能以本地回测股票名单替代。子查询保留源总数和实际观察
记录，来自父范围和子范围的记录可以互补；只把最终合并的唯一 ID 数量等于所请求范围
总数的结果作为完整索引交付。中间板块仍有缺行不能单独当成完整来源；若合并后整家
公司仍遗漏，总数约束仍会阻止成功。例：2018-04-20 的权益分派目录声明 101 条，
单日双向分页只能获得 95 个唯一 ID；板块拆分补齐到 101 条，说明仅按日期拆分仍会漏项。
数量一致也不能抵消已观察到的来源矛盾。三个真实公司窗口分别返回 83/94、38/45、63/64
两种总数；改为覆盖全部自然日、保留每次完整分页后，两轮结果仍分别为 83/83、45/41、
63/64。前一证券即使两轮相同，仍遗漏此前已返回的 11 个公告身份。因此不能取较小集合、
取最大数量，或用“两次相同”消除已经存在的缺口；须取得一致的官方目录，或另以发行人/
交易所完整披露目录逐项交叉核验，保留全部已观察身份和原失败。这里验证的是目录覆盖，
不能据此推断实际分红金额有误，见[原始查询与逐日复核](/home/wsw/app/maintenance-evidence/backtest-coverage-20261018-xncht91n/unstable-company-index-comparison.json)。
HTTP 成功和文件类型响应头也不保证原文有效。浦发银行 2023-07-06 的巨潮索引
`1217219068` 指向转股提示公告，但实际返回 HTTP 200、application/pdf，正文却是
“请求资源不存在”的 HTML 错误页。须以实际字节验证并保留失败；发行人官网检索到的
另一原文地址只是补核线索，尚未取得并核对原件时，不能填入该巨潮 ID 的缓存或据此
提交完整集合。原地址响应、摘要及发行人下载的 TLS 失败记录见

### 发布与重跑

原始公告集合、显式复核和生成 reviews 分开保存；具体 raw 路径由
[存储 owner](storage_layout.md)定义。`extraction.json` 的 inputs、issues 保存来源路径和逐候选提取诊断；诊断不等同于最终 unresolved，合法普通来源可执行时仍保留非阻塞的原文年份冲突。重跑重新执行提取，
直接比较当前结果决定是否重写。
补充提取缺少本地集合时记录未采集；Standard 由 `RefreshCorporateActionsStep` 调用
`ExtractDistributionTermsStep`，随后交给 `ResolveCorporateActionsStep` 处理普通来源及
已确认修正。提取缺项、表述未识别、报告期未匹配等只说明提取器没有取得事实，不能否决已完整
可执行的普通 dividend；它们继续留在提取清单中。原文中已提取到不同的税前金额或股份比例、
明确特殊受益对象、阶段日修订、相关更正未处理等，则是会影响本账户的业务冲突，保留
unresolved，不能用“只看普通股东”或“采用最新日期”掩盖。公开 PDF 可能采用 AES 编码且无需打开密码；解析环境使用
`pypdf[crypto]`，按[官方依赖说明](https://pypdf.readthedocs.io/en/stable/user/installation.html)
提供相应组件。AES-256 PDF 的密码校验和密钥派生由该库按文件格式处理，其中使用的
SHA-256 属于解密算法，不生成业务文件指纹，也不决定事实是否可用。删除该计算会使这类
公开原文无法解码；直接比较文件、来源路径或公开时间不能替代密钥派生。缺少运行依赖属于环境
失败，不能当成发行人没有分配。长园集团 `1204975071` 原文曾因此使 2018-07-11 整个
分区中断；补齐依赖后读取了同一摘要的 23 页，并重新产出 45 个 resolved 和 6 个
unresolved，见[真实失败与修复证据](/home/wsw/app/maintenance-evidence/backtest-coverage-20261018-xncht91n/aes-actual-announcement-result.json)。
采集与提取共用分配主题粗筛；定向 preparation 同时保留来源实施公告日的文件，允许正文
识别泛化标题。已有集合若记录 `missing_implementation` 或 `implementation_event_not_matched`，
再次显式 preparation 会重查对应发行人的原限定窗口，避免旧下载筛选永久隐藏候选。
该补查不扩展到所有历史日期，也不证明未知标题均已覆盖。标题末尾的“（已取消）”是索引中的文件撤回标记，
不单独表示取消权益分配。银亿《2020 年年度审计报告（已取消）》因此不进入必要事实提取，
不能以其空白解析结果阻塞已明确的权益；真正的分配取消、实施或更正公告仍保留。
相关 PDF 经 `pypdf` 无法解码或没有可提取文字时，按候选事件判断是否仍可能影响必要事实，
不把同一发行人的所有文件当成一个必需集合。明确属于其他期间且不匹配来源实施公告日的
文件不阻塞当前事件；分红回报规划不提供当次实施事实。已有完整原文确认当前事实时，
未提示修订的辅助法律意见或专项意见不再构成额外门槛；仍缺事实或涉及相关更正的不可读文件继续
记录 `pdf_text_unreadable`、来源、公告 ID 及错误类别。没有可匹配文件与已有文本但事件未匹配
分别记录 `missing_implementation`、`implementation_event_not_matched`；已匹配正文缺事实时
记录具体缺项。例如特殊零获配公告缺少完整分配范围，或现金安排无法区分普通股东权益
与投资人对价，记录 `ordinary_cash_entitlement_unconfirmed`；仅未写固定零分红句式不属于
此缺项。保留真正缺失的特殊事件待处理，不回退执行公司整体转增率。
不将解码失败当作空白无事件，也不阻断其他发行人的核验。已有完整人工核验按事件身份、条款和公开时间
处理该候选，不因其他 PDF 不可读而撤销。2018-06-21 集合中中天能源的核查文件 `1204921556` 触发
UTF-16 解码错误，即属于原文需另行阅读的情形。九月的威高血净 `1225562518`、确成股份
