## 分红送转数据

`dividend` 按 `record_date=YYYYMMDD` 查询。raw/processed 路径仍使用统一的
`trade_date=YYYY-MM-DD` 分区，该日期在此数据集表示股权登记日，不是公告日、除权日或
支付日。按登记日查询能够确定账户权益的归属；按除权日只查询回测区间会遗漏先前登记、
本期到账的权利，这些跨区间权利由初始账户显式携带，不能从当前持仓反推。

Broker 显式请求来源默认字段及非默认的 base_date、base_share；raw 保存原始 response。
`processed/dividend/v1` 保留以下列。新增来源字段仍使用当前版本，
已入库分区从原始 response 同步重建，版本规则由[存储 owner](storage_layout.md#processedfeatures-与-labels)定义：

| 字段 | 正式含义 |
| --- | --- |
| ts_code、symbol | 保留含交易所的来源证券身份，并另存六位展示代码 |
| ann_date | 源端预案、决案公告日；不等于最终条款的历史可见时间 |
| end_date | 利润分配所属报告期结束日 |
| div_proc | 源端分配进度；预案、预披露与实施不能混为同一事件 |
| imp_ann_date、record_date、ex_date、pay_date、div_listdate | 实施公告日、登记日、除权除息日、派息日、红股上市日 |
| cash_div_tax | 每股税前现金红利，元/原股份；不是每十股金额 |
| stk_div | 每股送转合计比例；不再次叠加 stk_bo_rate 或 stk_co_rate |
| base_date | 来源基准日；不替代登记日或公开可见日期 |
| base_share | 来源基准股本从万股乘10000转换为股，nullable float64；保留发布精度，不擅自取整 |

日期转换为 `YYYY-MM-DD`，每股现金和送转比例转换为十进制文本，源端 null 保留；分配进度仅去除首尾空白。
base_date/base_share 未提供时为 null，不补0，不借用 total_share/float_share。基准股本只表示
分配方案的来源观察，不是账户登记持股，也不参与替代普通股东每股条款；DividendRecord 保留
这两个可选事实，既有候选身份、条款选择及账户权益公式不变。
现金保持元/原股份，送转保持新增股/原股份；不按每十股或百分数再次缩放。来源单位见
[Tushare 分红字段](https://tushare.pro/document/2?doc_id=103)。仅靠单位转换不能恢复来源
已舍入的股本精度，公开可见性仍由各条款的实施公告时间决定。
状态修正不会补出缺失的实施公告日，`实施 ` 且公告为空仍属于待核实事实。股票分配记录
可以没有现金侧，现金分红记录可以没有送转侧；两侧都未知不能当成确定的零分配。零行
response 必须生成上述列齐全的空对象，明确区别于尚未采集。单次 response 达到接口
2,000 行上限时无法证明完整，下载失败，不提交可能截断的对象。

## 从来源记录到业务事件

本节唯一拥有 `corporate_actions/v1` 的数据语义。账户生命周期仍由
[公司行动与非交易账户事件](../offline_workflow_contract.md#公司行动与非交易账户事件)拥有。
`ResolveCorporateActionsStep` 在 dividend/v1 之后运行，按 `ts_code/end_date/record_date` 聚集
待解释记录。该键只是候选关联键，不是来源承诺的事件主键；不通过给公告行加序号或
ann_date 把重复记录变成多次到账，也不以数值一致证明分配对象相同。

### 普通来源准入与等价观察

普通分红送转以 `dividend/v1` 为主要来源；公告提供补充事实及已确认修正，逐笔公告核验
不是可执行事件的前置条件。
账户需要的是唯一的事件、普通股东的每股税前现金与送转比例、阶段日期及当时可见的条款；
这些事实可以由结构化来源提供。删除逐笔公告门槛后，这些必要事实和校验仍然存在，
因此该门槛不是记账的必要条件。反之，因 PDF 未采集或无法解析而拒绝一笔完整分红，会在
真实行情已经除息时漏记应收，不能把这类确定的缺项解释为更保守或更准确。

没有已确认修正时，同一候选先按实施公开时间选择适用方案，再归并等价观察；不要求恰好一行。
原始行与 dividend/v1 逐行保留。完整实施行按 imp_ann_date 选择较晚版本；较早实施方案以及
ann_date 明确早于该实施公告、但尚无实施公告日的旧观察，不继续否决后续实施方案。
例如新奥股份 2025-07-21 登记候选的旧观察为每股 0.81 元且没有实施公告日；
[2025-07-16 实施公告](https://static.cninfo.com.cn/finalpage/2025-07-16/1224176257.PDF)
及后续来源行明确每股 1.03 元，采用后者并从 07-17 才暴露条款。旧观察仍保留，不能把
1.03 元回填到旧预案的公告日。仅有更晚 ann_date 不证明实施方案已更正；无实施日期且
不能证明早于已知实施的观察仍为缺口。较晚缺项观察不能擦除较早明确事实，也不把不同
观察的互补缺项拼成合成行。单一来源方案必须在登记前已可见；需要登记后修订时，沿用
下述逐版本 review，不能把最终源行提前使用。

选择上述适用观察后，相同证券、报告期和登记日内，全部非空税前现金和送转比例
分别一致，除权、支付和上市日一致时，允许合并重复观察。预案／决案公告日 ann_date 的
差异不构成另一次实施。空金额表示该观察没有提供数值，不反驳另一行的明确金额。
优先采用现金和送转比例都明确的完整来源行，不将两条互补缺项拼成合成记录。没有完整行时，
若候选没有明确的非零现金，且存在一条正数送转、现金和派息日同时为空的原始观察，允许按
下述普通纯送转规则解释该观察；股份数量仍须由该行明确提供。例如 002226 的两条观察只有预案／决案
日期不同，实施日、每股 0.065 元和结算日期一致；持有 1,000 股应形成一次 65 元权益，
重复观察不应使权益变成未知或 130 元。同一实施公开时间的不同非空金额和不同阶段日分别保留
different_distribution_terms 与 different_phase_dates，不按条目顺序选择。

普通分红送转的来源实施公告日和除权日均须提供；优先在金额明确的完整行中选择，没有完整行才在可解释为
纯送转的原始行中选择。各组内按实施公告日取较晚者，相同实施公告日时按
ann_date 取较晚者（缺失排在已提供日期之前），只为稳定选择原始观察，不生成合成行。
ann_date 排序只用于等价观察，不能消除同一实施版本的真实冲突。条款从所选完整行的
imp_ann_date 结束后下一自然日 00:00 可见，避免采用较早的争议日期；缺值观察不把另一行
的明确金额提前到自己的公开日。所选实施公告日必须先于登记日，登记日先于除权日；
非零权益有对应支付或上市日，日期不早于除权日，零权益没有对应结算日。

普通送转范围仍限报告期为 03-31、06-30、09-30 或 12-31 的候选；明确正现金、零送转的
纯现金分红不受这一报告期限制。季度末不是现金分红可执行的必要事实，例如贵州茅台
2023 年特别分红的来源报告期为 11-21，每股现金 19.106 元，12-19 登记、12-20 除息及
支付，不能仅因报告期格式拒绝；金额、日期及股东范围见
[当时实施公告](https://www.sse.com.cn/disclosure/listedinfo/announcement/c/new/2023-12-14/600519_20231214_WR1C.pdf)。
非季度末的送转记录仍需明确分配性质与受益对象，不能
将重整总转增比例当作普通股东权益。

普通送转不要求来源显式填写现金零值：在上述普通范围内，正数送转及阶段日期有效，现金
和派息日同时为空，且没有明确非零现金、已确认现金权益或冲突时，将账户现金解释为零。
`dividend/v1` 与 `source_record.cash_div_tax` 保留原始 null，转换为可执行条款时才令
`cash_per_share = 0`，pay_date 仍为空；不增加来源标记、平行数据集或额外状态。null 保存
“供应商未填写数值”，0 表示“本次普通账户无现金权益”，不能混淆两个层次，也不将此规则
表述成供应商对所有空值的承诺。存在派息日、股份也为空、明确现金权益或冲突时不能按零
执行；零送转与空现金也不能据此认定 not_entitled。已确认修正仍优先，版本可见时间不变。

例如八一钢铁 600581 的 2018-04-19 登记来源为每股转增 1 股，现金与派息日为空，04-20
除权、04-23 上市。[当时实施公告](https://static.cninfo.com.cn/finalpage/2018-04-16/1204628906.PDF)
完整说明资本公积转增、全体股东及阶段日期，没有单独写“现金为零”。要求这句固定措辞
会把完整纯送转误作权益缺失。该例解释为零现金、每股新增 1 股，同时完整保留源行空值；
持有 100 股增加 100 股，不形成现金应收或支付。公告自动提取同样允许完整普通纯送转方案
不写零现金句子，但提到现金分配而金额无法确定，或存在尚未解释的现金支付安排时仍保留
缺口，不能把文字提取遗漏当成纯送转。

同一证券、登记日的其他候选（包括独立公告）尚未明确关联时，不自动选择一个或相加。
满足条件的结果保存所选的原始 `source_record`（包括上述可解释的现金 null），
action_id 为 `dividend:<candidate_id>:ordinary_shareholder`，reason 为 `ordinary_dividend_source`；
它表示采用来源事实，不表示已独立证明受益对象或核验公告。标准报告期只是限定本次普通
送转处理范围，不能证明不存在重整或差异化分配。已知特殊事件及冲突继续进入异常处理。

来源可见性不使用预案 ann_date 或本次采集时间提前暴露实施条款。公司行动链路信任
已接收的来源事实和已确认修正，不将文件被
替换、原始数据被事后改写作为运行时需要检测的失效模式；不为这些假设增加内容摘要、
快照绑定或重新核验门槛。已知更正仍按公开时间保存原版和修订版，不能将最终条款回填到
原公告日。登记前已公开分配安排、登记后才确定净分配比例的事件，按下述待定条款处理；
只有事后最终值、没有当时可见登记安排时仍保留未解决。这里的时间约束决定条款何时
可用于账户，不要求另建供应商历史版本或文件完整性证明。

### 已确认修正与候选关联

公告承担已确认修正、异常消歧、受益对象核实和来源遗漏补充。选择来源以阶段所缺的业务
事实为依据，不以 PDF 数量或逐篇完整提取为验收条件。普通来源已满足的事实不要求重复
公告证明；特殊事件须补齐适用于合资格普通持仓的净权益，不能用公司整体转增比例代替。
直接公布的净比例已足以计算时，不再强制要求公告同时给出分子、分母。不同公告可以提供
同一事件的不同阶段事实；已确认重复且不改变条款、身份、阶段或可见时间的材料不增加
入账门槛。首份公告缺少可独立执行的事实，后续完整实施公告在登记前已公开时，可以从后者
开始形成计划，不要求首份先通过提取。后续文件只公布除权参考价时，只更新参考事实，沿用
已经确认的普通股东权益和阶段日期；它不必重述现金、净获配比例和全部日期。任何时点只
使用已经公开的版本，不能将结果日期倒写到首次方案。尚未判明的相关更正与真实冲突不能
当作重复材料跳过；同日无法排序的不同值、阶段日冲突、晚到修订仍按下述限制处理。核验输入是
`raw/announcements/corporate_action_reviews/trade_date=<登记日>/reviews.json` 及其 Meta；
JSON 为 `CorporateActionReview` 数组。每项包含 candidate_id、related_sources、独立 action_id、
shareholder_scope、record_date、ex_date、pay_date、div_listdate、terms、evidence_refs、reason。
related_sources 是其他候选关联键的唯一列表；空列表表示该事件只关联主候选。
主候选不得再次出现在列表中，同一候选不能绑定到两个核验事件；关联候选必须属于同一证券和登记日。
跨候选关联必须由公告证明它们属于同一计划，不能仅凭相同证券、登记日、金额或不同报告期自动归并。
自动提取用证券身份、来源实施公告日和原文登记日关联事件，不要求来源报告期标签与
公告标题逐字一致；缺少实施公告日关联时，仍需正文或标题的期间与登记日共同确认。
标题只用于发现候选，不以“实施公告”“实施的公告”等固定结尾作为事实成立条件；
“事项实施的提示性公告”“实施暨风险提示的公告”和正文完整的进展公告均可提供实施事实。
正文仍须明确当前普通股东权益及必要阶段日；预案、尚需审批和已经取消的方案不能仅凭

名称及公开日关联事件，不必重述全部条款。仅修改公司汇总数、且明确其余内容不变的材料，
在变更字段不涉及每股权益、适用范围、阶段日或参考价时跳过；例如海泰新光
[2023-06-09 更正](https://static.cninfo.com.cn/finalpage/2023-06-09/1217021915.PDF)
仅更正新增无限售流通股总数，不能因此拒绝原文明确的每股现金 0.80 元、转增 0.4 股。

多个候选提取到同一个原生公告事件，且阶段日期、普通股东条款及公开版本完全一致时，

修正以候选身份关联来源，不绑定源行内容指纹；核验身份重复、没有有效来源的核验或非法
条款直接失败。同一候选内等价观察按上述来源规则归并；原始行继续保留，跨候选事件关联
和真实条款冲突不能通过删行消除。
公告链接及解释属于输入事实，不允许在回测代码里写股票代码特例。
`CollectAnnouncementsStep → ExtractDistributionTermsStep → ResolveCorporateActionsStep` 生产这些核验与解析事实；
采集边界、原文证据、人工复核输入及未覆盖能力见[公告流程](announcement_contract.md#announcement-verification-todo)。

经完整原文核验的实施公告也可独立产生 V1 事件，不要求 Tushare 已返回对应候选。
复核输入的 announcement_source 保存原生渠道、公告 ID、原证券代码、标题、公开日期、
已核实的精确公开时刻及原文 URL；candidate_id 为 `<渠道>:<公告ID>`，
action_id 为 `<渠道>:<公告ID>:ordinary_shareholder`。独立来源不能伪造 Tushare 行或报告期；

### 股东范围与版本条款

当前账户口径 `ordinary_shareholder` 只模拟符合该次分配资格的二级市场普通流通股持仓。
公告单列的大股东、回购专户、管理人、重整投资人、债权人，以及受特殊股份来源排除条款
影响的持仓，均不在模拟范围内。因此不建立股东名单或股份来源追踪状态，也不因公告存在
这些排除条款而否定已明确的合资格普通持仓权益。这是账户的建模前提，不是“所有个人
账户实际都合资格”的事实判断；税前记账也不能改变真实持仓资格。
在此范围内，以登记日收盘持仓数量乘以该事件适用于普通股东的实际净分配比例，不能仅凭
曾经买入判断权益，也不能套用公司整体转增比例或另一事件的中小股东比例。登记前卖出的
部分没有权益，登记后卖出不撤销已登记权益；普通股东实际净分配可以为零。
例如供销大集 2021-12-30 登记事件，公司每股总转增 2.2035714 股，合资格普通持仓每股
净获配 2.1898786 股，统一参考价为 1.80 元。被排除股东在指定期间转出的股份不获配这一
限制仍是真实公告事实，但该类持仓不由本模型表达。只看公司总比例会多记股份，只看价格
变化则会漏记普通股东实际获配，两者都不能替代具体事件的净权益。

terms 逐版本保存 published_date、可选 published_ts_us、cash_per_share、shares_per_share、
reference_cash_per_share、reference_shares_per_share 和可选 reference_price，已知金额与比例为 Decimal。
在显式确认的分配安排中，cash_per_share 或 shares_per_share 为 null 表示该项存在但数值待定，
支付、上市日期也可以分批披露；零表示明确无该项权益，不能把待定项填零。该解释用于
公告事实与账户阶段，不改变普通 dividend 缺项的准入规则。resolved 表示事件身份、登记安排
及条款含义已明确、可以驱动账户阶段，不保证每个阶段的数值已经可见；未到计算时点的
待定版本不否定该事件，计算时点仍无数值时由账户报告 pending_distribution_terms。
参考值有两种互斥表达：完整的一对参考现金和股份参数，或公告直接确定的正值 reference_price。
直接参考价不拆成虚构现金或股份；普通股东零权益也可以同时发生参考价调整。
两项公式参数必须同时为数值或同时为 null；三项参考值全为 null 只表示该早期权益版本
尚无可用参考值，不能据此推断价格不变。参考版本缺失不构成整笔事件拒绝；登记与确认权益不要求先知道市场参考价，
估值是否可用由工作流按行情和明确假设判断。已确认各版本普通股东现金
及新增股份均为零的事件，不以参考值完整为来源处置门槛；它不产生账户分配权益，估值缺口
由工作流按实际暴露和当时可见价格单独报告。供销大集 12 月 27 日实施公告提供权益和日期，
12 月 30 日提示公告才确定 1.80 元，不能把最终价格回填到首版。
已确认参考参数不能默认复制账户分配金额；source_record 本身不提供交易所参考事实。
只模拟普通股东不意味着将市场参考扣减当成普通股东现金。例如舒华体育 2024-05-08
登记事件，普通股东每股税前现金为 0.30 元，差异化除息参考扣减为 0.2974 元。
[实施公告](https://static.cninfo.com.cn/finalpage/2024-04-26/1219837422.PDF)同时存在一处
0.25 元表述，因此该案例曾被撤销自动批准；这是真实文字冲突，不是 0.30 与 0.2974
分别承担不同用途造成的歧义。同日公开的
[法律意见书第 3–4 页](https://static.cninfo.com.cn/finalpage/2024-04-26/1219837425.PDF)
明确普通股东每股 0.30 元，408,169,000 股对应现金总额 122,450,700 元，并另列参考扣减
0.2974 元，支持显式消歧。复核同时保留两份原件与说明，从 04-27 才暴露该版条款；
不能据此自动忽略其他公告中的金额冲突，也不必模拟回购专户的现金权益。
账户临时估值的处理及普通公式假设由[工作流 owner](../offline_workflow_contract.md#公司行动与非交易账户事件)定义。

事实版本按证据支持的可见时刻递增：只有日期时使用下一自然日 00:00；有原始索引
支持的精确时刻时保存 UTC 微秒 published_ts_us，并核对上海本地日期等于 published_date。
午夜占位不声明精确时间。后续公开的比例、日期、参考价只从该版可见时刻起使用，不能回填
首份公告。记录登记日实际持仓不依赖未来是否出现公告；后来才明确历史资格日时，只能读取
对应已保存快照，缺快照不能用当前持仓代替。事件日期存在真正矛盾时保留冲突，不能单凭
公告日期较新就消除；明确更正可更新尚未执行阶段，已确认或已结算权益不能静默改写。

例如 `002986`、`002727` 原公告的支付日早于除权日，原件及冲突均保留；更正公开后才形成
合法日程，不伪造更正前的可执行版本。雅博等事件的原文只有分配总数而没有分母，则是正常的
事实等待，不是日期矛盾或解析失败。已知数值不因后续公告省略而退回 null。参考价更新只作用
于还未被真实行情替代的临时估值；后补事实不使早期带缺口的净值变成完整收益。

### 补偿事件

补偿事件使用同一 V1 review，kind=compensation；普通分配为 kind=distribution。
补偿方转交已有股份或现金，并不等于公司按全体股东持仓实施分红送转。重整中由管理人
向普通受益股东划转、或依司法安排定向登记的合并净权益也使用这套阶段语义，不能把其中已包含的业绩补偿再计一次，
或把公司总股本增加比例当作个人获配比例。删除除权日门槛后，
补偿仍能由资格、净权益、条件、到账与公开版本唯一执行，因此 ex_date 对补偿可空，不补造
除权日或零参考参数。其市场参考价仅在另有明确安排时使用，不能复制获赠比例套普通公式。
普通 dividend 的直接解析范围不因此扩大；补偿由公告补充事实明确解释，并优先于原始源行。
公告发现包括业绩补偿实施、进展和完成文件；自动识别到补偿但尚无完整业务确认时报告
compensation_requires_review，不能把已存在的实施文件报告为 missing_implementation。

补偿 terms 的 benefit_state 分别为 conditional、confirmed、cancelled。条件未定与金额未定
不是同一状态：conditional 可以已有明确计算公式，仍不能确认确定资产；confirmed 的 null
金额表示确定参与但数量尚待公开，零表示明确无该项权益。取消的安排不执行，也不重用
同一身份重新发起；已确认权益转为取消需要独立账户调整，当前不自动支持。
已确认金额的后续更正保留新旧版本，未结算权益在公开时点调整差额；已支付现金或已到账
股份的更正需要独立账户调整，不能自动重复支付或覆盖此前账户状态。
在登记日 review 中，普通分配使用顶层阶段日期；补偿的 pay_date、shares_credit_date、shares_available_date
属于每个公开版本，顶层 pay_date、div_listdate 留空。披露日事实流则按每份公告保留阶段日期的到达顺序。
null 表示尚无已公开的确定阶段日期；
它不否定已明确的权益，也不把支付默认为立即发生。阶段日期不得早于资格日。
shares_available_date 表示股份的上市或解除交易限制日期，与普通账户的到账日期分别保存；
上市日已知、到账日未知或晚于上市日均不构成源事实矛盾。实际可卖必须同时满足到账与
上市条件，由账户执行边界保证。公告中的“预计”到账区间保留在核查依据中，不能任取
区间端点写成确定日期，也不能以管理人账户已收到股份代替普通账户到账。
后续确定的历史日期只能在该版公开后驱动尚未执行阶段。
有明确分子、分母时，shares_numerator 与 shares_denominator 保存原始整数，账户直接按
公式计算，不先舍入每股比例；否则采用明确的 shares_per_share，不强制补分母。
公式与公告约数的精度差异不构成整笔拒绝依据。

### 处置结果与重跑

每个候选组发布一个 resolution，保留 candidate_id、symbol、record_date、
status、reason、review、source_record。状态为 resolved、not_entitled 或 unresolved；
后者两个来源字段均为 null，前两者必须恰有一个来源：完整普通源记录或已确认 review。
not_entitled 需要来源可确认的零现金、零股份，不能仅由缺失字段推断；完整事件范围的限定
解释见下文。review 优先于 source_record，
同一事件不能同时执行二者。not_entitled 保留候选关联、公告依据和版本可见时间，用于阻止
把公司整体转增比例再次应用到普通账户；不创建零金额账户权益，也不要求额外收集所有
不涉及普通账户的公司公告。删除这项来源处置会失去对已知错误来源比例的覆盖，而删除零
权益登记不会改变现金、股数或应收，因此只保留前者。交投生态 2025-12-11 登记事件的
[实施公告](https://static.cninfo.com.cn/finalpage/2025-12-06/1224855300.PDF)第 3 页明确转增
股票不向原出资人分配，第 5 页明确现金红利为零。公司每 10 股转增 14.50 股不能成为
普通账户获配比例；条件公式中的 6.31 元也不能成为最终参考价。该来源可以处置为
not_entitled，即使当时尚未编译特殊除权公式，相关估值限制仍须如实保留。
“重整”本身也不是必须人工复核的理由。正文明确全部新增股份不向原股东分配，且没有
另轮获配或混合补偿时，现金可以由明确的零分红表述确认，也可以由完整实施方案的事件
范围确认：当次转增全部用于引入投资人和清偿债务，完整分配方案没有普通股东现金分配，
已出现的现金仅为投资人向上市公司支付的对价，则本事件的普通账户现金权益为零。
一般交易规则引文中的“现金红利”变量不表示公司实际派息；投资人受让价格也不表示
向普通股东支付的现金。这里确认的是已完整说明的当次分配，不是从 dividend 的 null
推断现金为零，更不是断言公司不存在其他现金事件。不能要求原文另造一句“不涉及现金
红利”才能确认该业务事实。自动提取须定位完整的资本公积转增方案及其受益去向；缺少
方案正文、具体分配另行披露、出现无法解释的现金安排或普通股东现金补偿时，仍记录
具体缺项。只排除部分股份、特定账户或某一轮转增不满足零权益条件；公司转增率和
债权人获配也不能替代普通账户净权益。豆神教育
[2023-12-20 原文](https://static.cninfo.com.cn/finalpage/2023-12-20/1218675470.PDF)

零获配、不涉及现金红利、12-26 登记及 12-27 除权，可先确认 not_entitled；
[12-27 结果](https://static.cninfo.com.cn/finalpage/2023-12-27/1218734554.PDF)的 2.52 元

第 3—4 页完整分配方案将全部转增股份用于投资人受让和偿债，第 5 页的现金为投资人支付

Parquet 的物理列为 symbol、record_date、

无法按上述规则解释的缺字段、同登记日未关联候选、真实条款冲突和特殊事件仍保留 unresolved，
